# Коммит и пуш

Сразу вызови `Agent` с `subagent_type: "committer"`, `model: "haiku"` и `run_in_background: false`. Ничего не делай до этого: не запускай `git status`, не читай диффы, не составляй сообщение коммита — весь смысл скилла в том, чтобы этим занимался дешёвый агент, а не основная модель.

В `prompt` передай:

- нужно ли пушить (по умолчанию — да, если пользователь сказал «запушь»/«пушим»; иначе только коммит);
- ограничения по файлам, если пользователь их назвал («только back/», «без .gitignore»);
- одну-две фразы о сути изменений, если ты знаешь её из текущей сессии, — это экономит агенту чтение диффов. Если не знаешь, ничего не выдумывай, агент разберётся сам.

Когда агент вернёт результат, перескажи пользователю коротко: хеш и заголовок коммита, что вошло, прошёл ли пуш. Не пересказывай весь отчёт целиком.

Если агент сообщил об ошибке (конфликт rebase, отклонённый пуш, отсутствие изменений) — передай её пользователю как есть и не пытайся чинить сам, пока он не попросит.
