# AGENTS.md — фронтенд flatnik (React + Zustand + TanStack Query)

Конвенции пакета `front`. Общее о монорепозитории — в корневом `AGENTS.md`.

## Контекст

- React 18 + Vite 5, ESM, TypeScript `strict: true`, `noEmit`.
- Серверное состояние — TanStack Query 5, клиентское — Zustand 5;
  `QueryClientProvider` поднят в `src/main.tsx`.
- Типы API — из `@flatnik/shared`: сгенерированы из OpenAPI-схемы бэкенда,
  руками не пишутся и не правятся.
- Все запросы — на относительный `/api/...` (гейтвей держит единый origin);
  абсолютных URL бэкенда в коде нет.
- Полная сборка (`npm run build --workspace=@flatnik/front`) нужна только когда важен
  бандл: к проверке типов она добавляет `vite build` и ничего не проверяет сверх неё.

## Обязательная проверка: `lint`

**Добавил или изменил любой `.ts`/`.tsx` в `front/` на любом уровне вложенности —
в конце работы запусти:**

```bash
npm run lint --workspace=@flatnik/front
```
- Тестов и линтеров в проекте нет, `tsc` в `strict` — единственная автоматическая
  обратная связь. Правил только CSS, разметку или конфиг — запускать не нужно.

## Стиль

- Без точек с запятой, одинарные кавычки, отступ 2 пробела.
- Функциональные компоненты, именованный экспорт, без `React.FC`; `import type` для типов.
- Хуки в `use*.ts`, компоненты в `*.tsx` с PascalCase-именем. Без `any` —
  `unknown` + сужение.

## Структура — по фичам

```
src/
  app/                  # провайдеры, роутинг
  pages/                # компоненты маршрутов: связывают фичи между собой
  shared/
    api/                # fetcher, queryClient, хелперы запросов
    lib/                # хелперы и хуки без разметки
    ui/                 # переиспользуемые примитивы
  features/<feature>/
    api/  model/  ui/   # запросы, zustand-стор, компоненты
```

Импорты вниз по иерархии: `pages` → `features` → `shared`, не наоборот. Кросс-импорты
между фичами — сигнал поднять общее в `shared` или связать их на уровне страницы:
страница для того и нужна, она играет роль медиатора.

## TanStack Query — все данные с API

`useEffect` + `fetch` + `useState` для загрузки не пишем: теряются кеш, дедупликация
и обработка гонок.

- HTTP-вызовы живут в `features/<feature>/api/` и идут через единый `fetcher`
  из `shared/api` (проверка `res.ok`, типизированная ошибка). Компонент вызывает хук.
- Запросы описываем через `queryOptions`; тип ответа — из `@flatnik/shared`.
- Ключ — массив от общего к частному (`['reviews', 'detail', id]`), собирается
  фабриками в `api/`-модуле. Все параметры `queryFn` входят в ключ, иначе — залипший кеш.
- Мутации: `useMutation` + `invalidateQueries` по префиксу в `onSuccess`; не дёргаем
  `refetch()` руками. Оптимистичные обновления — только с откатом в `onError`.
- Обрабатываем все ветки: `isPending`, `error`, данные. Компонент только с веткой
  успеха не закончен.
- Глобальные `retry`/`staleTime` — в `QueryClient`, не копипастой по хукам.

## Zustand — только клиентское UI-состояние

Серверные данные живут в кеше Query; их копия в сторе — источник расхождений.
В сторе: фильтры, черновики форм, модалки, настройки отображения.

- Один стор на фичу: `features/<feature>/model/<feature>.store.ts`. Тип состояния
  явный, действия внутри стора рядом с данными.
- Подписка селектором (`useStore((s) => s.city)`), не стором целиком; селектор,
  возвращающий новый объект/массив, — через `useShallow`.
- Не храним производное — считаем на месте.
- Локальный `useState` — норма, пока состояние не нужно нескольким несвязанным
  компонентам.

## Рендеринг

- Ключи списков — стабильный `id`, не индекс. `useMemo`/`useCallback` — по факту
  заметной стоимости.
- `StrictMode` включён: эффекты идемпотентны и с очисткой.

## Перед сдачей

1. `npm run lint --workspace=@flatnik/front` проходит. Трогал конфиг Vite или
   зависимости — прогони и полную сборку.
2. Экран проверен на всех состояниях: загрузка, ошибка, пусто, успех; в консоли
   браузера нет предупреждений React.
3. В диффе нет `console.log`, закомментированного кода и временных моков.

## Чего не делать

- Не грузить данные в обход Query; не дублировать серверные данные в Zustand.
- Не писать типы API руками и не править `shared/src/api.generated.ts` —
  недостающий тип чинится на бэкенде (`npm run openapi` в корне).
- Не хардкодить адрес бэкенда — только относительный `/api/...`.
- Не добавлять UI-библиотеки, роутеры и прочие крупные зависимости без согласования.
- Не заводить ESLint/Prettier/тесты походя: их в проекте нет, это отдельное решение.
