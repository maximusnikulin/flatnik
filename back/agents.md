# AGENTS.md — бэкенд flatnik (NestJS)

Конвенции пакета `back`. Общее о монорепозитории — в корневом `AGENTS.md`.

## Контекст

- NestJS 10 (Express-адаптер), TypeScript, CommonJS, `strict: true`.
- Глобальный префикс `api`, порт из `PORT`, слушаем `0.0.0.0` — приложение живёт в контейнере.
- `npm run build --workspace=@flatnik/back` (`nest build`) нужен, когда важен собранный
  код: перед `npm run openapi` (CLI-плагин Swagger работает только на выходе компиляции)
  и перед запуском `dist/main.js`.

## Обязательная проверка: `lint`

**Добавил или изменил любой `.ts` в `back/` на любом уровне вложенности — в конце
работы запусти:**

```bash
npm run lint --workspace=@flatnik/back
```

Скрипт собирает `shared` и прогоняет `tsc --noEmit` по `back`: `dist` не трогает,
`nest build` не запускает. Задача не сдана, пока он не прошёл с нулевым кодом.

- Тестов и линтеров в проекте нет, `tsc` в `strict` — единственная автоматическая
  обратная связь. Менялся контракт — `lint` не заменяет `npm run openapi`: схема
  генерируется только из собранного кода (см. раздел про OpenAPI).

## Стиль и архитектура

- Как в существующем `src`: без точек с запятой, одинарные кавычки, отступ 2 пробела.
- `import type` для чисто типовых импортов; явные типы возвращаемых значений
  у контроллеров и сервисов; без `any` — `unknown` + сужение.
- Модуль на фичу: `src/<feature>/` с module/controller/service/dto, один класс — один
  файл, регистрация в `AppModule` через `imports`.
- Контроллер — только HTTP-слой; бизнес-логика в сервисах; зависимости через DI-конструктор.
- Ошибки — исключениями Nest (`NotFoundException`, `BadRequestException`, ...), а не
  `{ error }` со статусом 200. Секреты и stack trace клиенту не возвращаем.
- Логи через `Logger` с контекстом класса, не `console.log`.
- Конфигурация только из переменных окружения; новые переменные добавляем в оба
  compose-файла (`docker-compose.yml` и `docker-compose.prod.yml`) и в README.

## OpenAPI: код → схема → типы фронта

Источник истины — DTO-классы бэкенда (именно классы: декораторам нужна рефлексия,
`interface` не годится). `npm run openapi` в корне генерирует `shared/openapi.json`
и `shared/src/api.generated.ts` — оба артефакта коммитим вместе с кодом и руками
не правим. Расхождение схемы с DTO = сломанная сборка.

- Валидация: DTO + глобальный `ValidationPipe` (whitelist, transform) уже подключён
  в `src/app.config.ts`. Поля без декораторов `class-validator` отсекаются — каждое
  поле DTO валидируется явно.
- CLI-плагин Swagger (`nest-cli.json`) выводит типы из TypeScript и `class-validator`;
  `@ApiProperty` — только где вывода недостаточно (union, `oneOf`, примеры). Плагин
  работает только на собранном коде, поэтому `npm run openapi` включает `nest build`.
- На методах контроллера — `@ApiOkResponse({ type: XResponseDto })` и ошибочные
  ответы; для массивов `isArray: true` обязателен. Контроллеры группируем `@ApiTags`.
- Публичные алиасы типов — в `shared/src/index.ts`
  (`HealthResponse = Schemas['HealthResponseDto']`), фронт импортирует `@flatnik/shared`.
- Swagger UI — `/api/docs` (выключается `SWAGGER_UI=off`).

## Обратная совместимость контракта

Ломающие изменения для **существующих** полей и эндпоинтов в `shared/openapi.json`:
смена типа или `format`, изменение обязательности, удаление/переименование, сужение
enum или ограничений валидации, смена семантики при том же типе (секунды → миллисекунды —
компилятор не поймает). Не ломает: новое опциональное поле, новый эндпоинт, расширение
enum ответа, ослабление валидации входа.

Обязательное поведение:

1. **Остановись и предупреди пользователя до правки**: какое поле, из какого типа
   в какой, что сломается (фронт, БД и миграция данных, кэши). Даже если задача
   сформулирована как прямое указание «поменяй тип».
2. Предложи совместимый вариант: новое поле рядом со старым (`deprecated: true`),
   версионирование эндпоинта. Ломающее одним коммитом допустимо, пока единственный
   клиент — наш фронт, и только вместе с его правками в том же коммите.
3. Согласовано — доведи по всей цепочке: DTO, хранилище и миграция, фронт, перегенерация.

Индикатор — дифф `shared/openapi.json`: изменённые и удалённые строки в существующих
схемах просматривай глазами перед коммитом.

## Перед сдачей

1. `npm run lint --workspace=@flatnik/back` проходит.
2. Менялся контракт — прогнан `npm run openapi`, оба артефакта в коммите, в диффе
   схемы нет несогласованных ломающих изменений.
3. `shared` пересобран, фронт компилируется на новых типах.
4. Эндпоинт проверен (`curl .../api/<route>`), схема видна в `/api/docs`.
5. В диффе нет `console.log`, закомментированного кода и временных заглушек.

## Чего не делать

- Не редактировать сгенерированные файлы; не переходить на schema-first.
- Не менять `tsconfig.json`, Dockerfile'ы и compose-файлы попутно с фичей.
- Не обращаться к БД из контроллера; не глушить `strict` через `@ts-ignore`/`any`.
- Не добавлять зависимости без необходимости; `@nestjs/swagger` держим на `^8` —
  v11 требует Nest 11.
